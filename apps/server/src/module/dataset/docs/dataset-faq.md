# 数据集模块常见问题解答（FAQ）

## 基础问题

### 1. 什么是数据集？

**答**：数据集是系统中用于管理和组织数据的核心概念，代表一个完整的数据集合，包含多个表、字段、指标和表间关联关系。数据集支持语义型和宽表型两种类型，通过关联数据源和数据表，构建完整的数据模型。

### 2. 数据集模块的主要功能是什么？

**答**：数据集模块主要提供以下功能：
- 创建数据集：从数据源选择表和字段，构建数据模型
- 查询数据集：获取数据集的完整信息，包括关联的表、字段、指标和关联关系
- 更新数据集：修改数据集的基本信息和关联实体
- 删除数据集：删除指定的数据集

### 3. 数据集的类型有哪些？

**答**：数据集支持两种类型：
- **语义型（semantic）**：基于语义模型构建的数据集，支持复杂的关联关系和指标计算
- **宽表型（wide）**：将多个表的数据整合到一个宽表中，适合简单的数据分析场景

## 创建数据集相关问题

### 4. 创建数据集时需要哪些参数？

**答**：创建数据集时需要以下参数：
- `datasourceId`：数据源 ID
- `datasourceTableIds`：选中的数据表 ID 列表
- `name`：数据集名称
- `description`：数据集描述（可选）
- `mainTableId`：主表 ID（可选）
- `fields`：数据集字段列表
- `joins`：表关联关系列表（可选）

### 5. 为什么创建数据集时提示「数据源不存在」？

**答**：这是因为请求中的 `datasourceId` 对应的数据源不存在。请确保：
- 数据源已正确创建
- `datasourceId` 参数值正确
- 数据源状态为激活状态

### 6. 为什么创建数据集时提示「部分数据表不存在」？

**答**：这是因为请求中的 `datasourceTableIds` 列表中包含不存在的数据表。请确保：
- 所有指定的数据表都存在于数据源中
- 数据表 ID 列表中的值正确
- 数据表已被正确添加到数据源中

### 7. 为什么创建数据集时提示「数据集字段不能为空」？

**答**：这是因为创建数据集时必须包含至少一个字段。请确保：
- 请求中包含 `fields` 字段
- `fields` 列表至少有一个元素
- 每个字段的信息完整且有效

### 8. 为什么创建数据集时提示「表的主键字段必须包含在数据集中」？

**答**：这是因为每个表的主键字段必须包含在数据集中，以确保数据的完整性和关联关系的正确性。请确保：
- 每个表的主键字段都包含在 `fields` 列表中
- 主键字段的 `isPrimaryKey` 属性设置为 `true`

### 9. 为什么创建数据集时提示「数据源没有外键关系，需要配置表之间的关联关系」？

**答**：这是因为当未手动指定表之间的关联关系时，系统会尝试使用数据源的外键关系。如果数据源没有外键关系，则需要手动配置关联关系。请确保：
- 手动配置表之间的关联关系，在 `joins` 字段中指定
- 或确保数据源中存在外键关系

## 查询和使用数据集相关问题

### 10. 如何查询所有数据集？

**答**：使用 `GET /dataset` 接口可以查询所有数据集的完整信息，包括关联的表、字段、指标和关联关系。

### 11. 如何查询单个数据集的详细信息？

**答**：使用 `GET /dataset/:id` 接口，其中 `:id` 是数据集的 ID，可以查询单个数据集的完整信息。

### 12. 查询数据集时返回的数据结构包含哪些信息？

**答**：查询数据集时返回的数据结构包含以下信息：
- 数据集基本信息（ID、名称、描述、类型、状态）
- 数据源信息
- 主表信息
- 关联的表列表
- 字段列表
- 指标列表
- 关联关系列表

### 13. 如何使用数据集进行数据分析？

**答**：使用数据集进行数据分析的步骤：
1. 创建包含所需表和字段的数据集
2. 定义表之间的关联关系
3. 创建必要的指标
4. 使用查询接口获取数据集信息
5. 基于返回的数据构建分析报表

## 更新数据集相关问题

### 14. 如何更新数据集的基本信息？

**答**：使用 `PATCH /dataset` 接口，在请求体中包含 `dataSetId`、`name` 和 `description` 字段，可以更新数据集的基本信息。

### 15. 如何向数据集添加新字段？

**答**：使用 `PATCH /dataset` 接口，在请求体中包含 `dataSetId` 和 `fields` 字段，其中 `fields` 是一个包含 `action: "addField"` 的对象列表，可以向数据集添加新字段。

### 16. 如何更新数据集的指标？

**答**：使用 `PATCH /dataset` 接口，在请求体中包含 `dataSetId` 和 `metrics` 字段，其中 `metrics` 是一个包含 `action`（如 "addMetric"、"updateMetric"、"removeMetric"）的对象列表，可以更新数据集的指标。

### 17. 更新数据集时为什么需要使用事务？

**答**：更新数据集时使用事务可以确保所有操作的原子性，避免部分更新成功而部分失败的情况，保证数据的一致性和完整性。

## 技术问题

### 18. 数据集模块使用了哪些技术？

**答**：数据集模块使用了以下技术：
- NestJS 框架
- TypeORM ORM 框架
- 数据库（MySQL/PostgreSQL 等）
- 事务处理
- 批量查询优化

### 19. 如何优化数据集查询性能？

**答**：优化数据集查询性能的方法：
- 使用批量查询减少数据库查询次数
- 使用索引提高查询速度
- 合理使用关联关系的加载策略
- 避免在查询中使用复杂的计算和过滤条件

### 20. 数据集模块的错误处理机制是什么？

**答**：数据集模块使用 `ExceptionFactory` 统一处理错误，提供清晰的错误信息，支持不同类型的错误处理策略。常见的错误类型包括：
- 数据源不存在
- 数据表不存在
- 字段验证错误
- 关联关系错误

### 21. 如何调试数据集模块的问题？

**答**：调试数据集模块问题的方法：
- 使用 `console.log()` 输出关键信息
- 检查数据库中的数据是否正确
- 使用 Postman 或其他 API 测试工具测试接口
- 仔细阅读错误信息，定位问题所在
- 检查数据源和数据表的配置

## 最佳实践

### 22. 创建数据集时的最佳实践是什么？

**答**：创建数据集时的最佳实践：
- 选择合适的数据源和数据表
- 确保包含所有必要的字段，特别是主键字段
- 合理定义表之间的关联关系
- 设置有意义的字段名称和业务名称
- 为数据集添加详细的描述

### 23. 如何设计高效的数据集结构？

**答**：设计高效数据集结构的方法：
- 选择必要的表和字段，避免包含过多不必要的数据
- 合理设置主表，减少关联查询的复杂度
- 使用适当的连接类型（内连接、左连接、右连接）
- 为频繁查询的字段创建索引
- 合理组织指标，避免重复计算

### 24. 如何管理大型数据集？

**答**：管理大型数据集的方法：
- 合理分区和分表
- 使用缓存减少数据库负载
- 定期优化和清理数据
- 监控数据集的使用情况
- 考虑使用数据仓库技术处理大规模数据

### 25. 数据集模块的扩展性如何？

**答**：数据集模块具有良好的扩展性：
- 使用枚举类型定义状态和类型，便于后续扩展
- 使用 JSON 字段存储复杂配置，提高灵活性
- 使用管理器模式处理不同类型的实体操作
- 支持不同类型的数据集和指标
- 模块化设计，便于添加新功能

## 故障排除

### 26. 数据集创建失败怎么办？

**答**：数据集创建失败的排查步骤：
1. 检查数据源是否存在
2. 检查数据表是否存在
3. 检查字段列表是否为空
4. 检查主键字段是否包含在数据集中
5. 检查关联关系是否正确配置
6. 查看错误信息，定位具体问题

### 27. 数据集查询速度慢怎么办？

**答**：数据集查询速度慢的优化方法：
1. 使用批量查询减少数据库查询次数
2. 为常用查询字段创建索引
3. 优化关联关系的加载策略
4. 减少返回数据的大小
5. 考虑使用缓存

### 28. 数据集更新失败怎么办？

**答**：数据集更新失败的排查步骤：
1. 检查数据集是否存在
2. 检查请求参数是否正确
3. 检查字段、指标、关联关系和表的更新操作是否有效
4. 查看错误信息，定位具体问题
5. 确保使用事务处理更新操作

### 29. 数据集删除后如何恢复？

**答**：数据集删除后，默认情况下无法直接恢复。建议：
- 在删除前备份数据集信息
- 考虑使用软删除（将状态设置为 DELETED）而不是物理删除
- 定期备份数据库，以便在需要时恢复数据

### 30. 如何处理数据集的版本管理？

**答**：处理数据集版本管理的方法：
- 为数据集添加版本号字段
- 保存数据集的历史变更记录
- 实现数据集的回滚功能
- 定期备份数据集配置
- 使用版本控制工具管理数据集定义

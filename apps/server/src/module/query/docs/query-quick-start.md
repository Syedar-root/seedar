# 查询模块快速入门指南

## 概述

本指南将帮助您快速上手查询模块，了解如何创建、管理和执行查询。查询模块是一个功能强大的工具，用于定义和执行数据查询，支持复杂的数据分析需求。

## 环境准备

在使用查询模块之前，您需要确保以下环境已准备就绪：

1. **后端服务运行**：确保服务器已经启动并运行
2. **数据集配置**：需要先创建数据集并配置数据源
3. **API访问权限**：确保您有访问查询API的权限

## 基本概念

在开始使用查询模块之前，了解以下基本概念将有助于您更好地理解和使用该模块：

### 1. 查询 (Query)

查询是对数据的请求，包含查询名称、关联的数据集、查询逻辑（DSL）和状态等信息。

### 2. DSL (Domain Specific Language)

DSL是查询的领域特定语言，用于定义查询的具体逻辑，包括：
- 主表选择
- 维度设置
- 指标选择
- 筛选条件
- 表连接配置

### 3. 数据集 (Dataset)

数据集是查询的基础，包含表结构、字段、指标等信息，关联到具体的数据源。

### 4. 数据源 (Datasource)

数据源是实际存储数据的地方，如MySQL、PostgreSQL等数据库。

## 快速开始

### 步骤1：创建查询

**功能说明**：创建一个新的查询定义

**请求示例**：

```bash
curl -X POST http://localhost:3000/query \
  -H "Content-Type: application/json" \
  -d '{
    "name": "销售数据分析",
    "datasetId": 1,
    "dsl": {
      "datasetId": 1,
      "tableId": 1,
      "dimensions": [1, 2],
      "metrics": [
        {
          "id": 1,
          "alias": "销售额"
        }
      ],
      "filters": [
        {
          "fieldId": 3,
          "op": "=",
          "value": "2024"
        }
      ],
      "joins": [
        {
          "id": 1,
          "type": "left"
        }
      ]
    },
    "status": "active"
  }'
```

**响应示例**：

```json
{
  "id": 1,
  "name": "销售数据分析",
  "datasetId": 1,
  "dsl": {...},
  "status": "active",
  "createdAt": "2024-01-01T00:00:00.000Z",
  "updatedAt": "2024-01-01T00:00:00.000Z"
}
```

### 步骤2：获取查询列表

**功能说明**：获取所有查询或按状态筛选查询

**请求示例**：

```bash
# 获取所有查询
curl http://localhost:3000/query

# 按状态筛选查询
curl http://localhost:3000/query?status=active
```

**响应示例**：

```json
[
  {
    "id": 1,
    "name": "销售数据分析",
    "datasetId": 1,
    "status": "active",
    "createdAt": "2024-01-01T00:00:00.000Z",
    "updatedAt": "2024-01-01T00:00:00.000Z"
  }
]
```

### 步骤3：执行查询

**功能说明**：执行指定的查询并返回结果

**请求示例**：

```bash
curl -X POST http://localhost:3000/query/execute \
  -H "Content-Type: application/json" \
  -d '{"queryId": 1}'
```

**响应示例**：

```json
{
  "sql": "SELECT date, SUM(amount) FROM sales WHERE year = 2024 GROUP BY date",
  "results": {
    "header": ["日期", "销售额"],
    "rows": [
      ["2024-01-01", "10000"],
      ["2024-01-02", "15000"]
    ]
  },
  "executionTime": 150
}
```

### 步骤4：更新查询

**功能说明**：更新现有查询的定义

**请求示例**：

```bash
curl -X PATCH http://localhost:3000/query/1 \
  -H "Content-Type: application/json" \
  -d '{
    "name": "销售数据分析（更新）",
    "dsl": {
      "datasetId": 1,
      "tableId": 1,
      "dimensions": [1, 2, 4],
      "metrics": [
        {
          "id": 1,
          "alias": "销售额"
        },
        {
          "id": 2,
          "alias": "订单数"
        }
      ],
      "filters": [
        {
          "fieldId": 3,
          "op": "=",
          "value": "2024"
        }
      ]
    }
  }'
```

**响应示例**：

```json
{
  "id": 1,
  "name": "销售数据分析（更新）",
  "datasetId": 1,
  "dsl": {...},
  "status": "active",
  "createdAt": "2024-01-01T00:00:00.000Z",
  "updatedAt": "2024-01-01T00:00:00.000Z"
}
```

### 步骤5：删除查询

**功能说明**：删除指定的查询

**请求示例**：

```bash
curl -X DELETE http://localhost:3000/query/1
```

**响应**：
- 成功：200 OK（无响应体）
- 失败：404 Not Found（查询不存在）

## DSL 编写指南

### 1. 维度 (dimensions)

维度用于对数据进行分组，支持两种格式：

- **简单格式**：直接使用字段ID
  ```json
  "dimensions": [1, 2, 3]
  ```

- **带别名格式**：指定字段ID和别名
  ```json
  "dimensions": [
    1,
    {"fieldId": 2, "alias": "产品类别"}
  ]
  ```

### 2. 指标 (metrics)

指标用于计算和聚合数据，格式为：

```json
"metrics": [
  {
    "id": 1, // 指标ID
    "alias": "销售额" // 可选别名
  }
]
```

### 3. 筛选条件 (filters)

筛选条件用于过滤数据，格式为：

```json
"filters": [
  {
    "fieldId": 3, // 字段ID
    "op": "=", // 操作符
    "value": "2024" // 值
  }
]
```

**支持的操作符**：
- `=`：等于
- `!=`：不等于
- `>`：大于
- `<`：小于
- `>=`：大于等于
- `<=`：小于等于
- `like`：模糊匹配
- `in`：在范围内
- `not_in`：不在范围内
- `is_null`：为空
- `is_not_null`：不为空
- `recent_days`：最近几天

### 4. 表连接 (joins)

表连接用于关联多个表，格式为：

```json
"joins": [
  {
    "id": 1, // 连接ID
    "type": "left" // 连接类型：left, inner, right, full
  }
]
```

## 故障排除

### 1. 查询执行失败

**症状**：执行查询时返回错误

**可能原因**：
- DSL格式错误
- 数据集或数据源不存在
- 数据源配置错误
- SQL执行错误

**解决方案**：
- 检查DSL格式是否正确
- 确保数据集和数据源存在且配置正确
- 查看错误信息，定位具体问题

### 2. 查询结果为空

**症状**：查询执行成功，但返回空结果

**可能原因**：
- 筛选条件过于严格
- 数据不存在
- DSL配置错误

**解决方案**：
- 检查筛选条件是否合理
- 验证数据源中是否存在对应数据
- 检查DSL配置是否正确

### 3. 性能问题

**症状**：查询执行时间过长

**可能原因**：
- 查询过于复杂
- 数据量过大
- 数据库索引缺失

**解决方案**：
- 优化DSL，减少不必要的维度和指标
- 添加适当的筛选条件，减少数据量
- 确保数据库表有适当的索引

## 最佳实践

1. **命名规范**：为查询使用清晰、描述性的名称
2. **状态管理**：使用合适的状态管理查询生命周期
3. **DSL设计**：
   - 只包含必要的维度和指标
   - 使用适当的筛选条件减少数据量
   - 合理使用表连接，避免复杂的多表关联
4. **性能优化**：
   - 对频繁执行的查询考虑结果缓存
   - 监控查询执行时间，优化慢查询
   - 定期检查和清理不再使用的查询

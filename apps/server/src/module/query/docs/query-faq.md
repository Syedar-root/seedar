# 查询模块常见问题解答 (FAQ)

## 概述

本文档汇总了使用查询模块时常见的问题和解答，帮助您快速解决使用过程中遇到的问题。

## 基础问题

### 1. 什么是查询模块？

**解答**：查询模块是一个负责管理和执行数据查询的核心模块，它提供了完整的查询生命周期管理，包括创建、更新、执行等功能。该模块通过 DSL (Domain Specific Language) 定义查询逻辑，并将其转换为可执行的 SQL 语句。

### 2. 什么是 DSL？

**解答**：DSL (Domain Specific Language) 是查询的领域特定语言，用于定义查询的具体逻辑，包括主表选择、维度设置、指标选择、筛选条件和表连接配置等。

### 3. 查询模块支持哪些数据库类型？

**解答**：查询模块通过数据源模块支持多种数据库类型，包括 MySQL、PostgreSQL 等常见数据库。具体支持的数据库类型取决于数据源模块的配置。

## 操作问题

### 4. 如何创建一个查询？

**解答**：创建查询需要发送 POST 请求到 `/query` 接口，提供查询名称、数据集 ID、DSL 定义和状态等信息。具体示例可参考快速入门指南。

### 5. 如何执行查询？

**解答**：执行查询需要发送 POST 请求到 `/query/execute` 接口，提供查询 ID。系统会根据查询的 DSL 生成 SQL 语句并执行，返回查询结果。

### 6. 如何更新查询？

**解答**：更新查询需要发送 PATCH 请求到 `/query/:id` 接口，提供要更新的字段，如名称、DSL、状态等。

### 7. 如何删除查询？

**解答**：删除查询需要发送 DELETE 请求到 `/query/:id` 接口，指定要删除的查询 ID。

## DSL 相关问题

### 8. DSL 中支持哪些操作符？

**解答**：DSL 支持以下操作符：
- `=`：等于
- `!=`：不等于
- `>`：大于
- `<`：小于
- `>=`：大于等于
- `<=`：小于等于
- `like`：模糊匹配
- `in`：在范围内
- `not_in`：不在范围内
- `is_null`：为空
- `is_not_null`：不为空
- `recent_days`：最近几天

### 9. 如何在 DSL 中定义维度？

**解答**：维度用于对数据进行分组，支持两种格式：
- 简单格式：直接使用字段 ID，如 `"dimensions": [1, 2, 3]`
- 带别名格式：指定字段 ID 和别名，如 `"dimensions": [1, {"fieldId": 2, "alias": "产品类别"}]`

### 10. 如何在 DSL 中定义指标？

**解答**：指标用于计算和聚合数据，格式为：
```json
"metrics": [
  {
    "id": 1, // 指标 ID
    "alias": "销售额" // 可选别名
  }
]
```

### 11. 如何在 DSL 中定义表连接？

**解答**：表连接用于关联多个表，格式为：
```json
"joins": [
  {
    "id": 1, // 连接 ID
    "type": "left" // 连接类型：left, inner, right, full
  }
]
```

## 错误处理

### 12. 执行查询时返回 "Query with ID X not found" 错误？

**解答**：这表示您指定的查询 ID 不存在。请检查查询 ID 是否正确，或确认该查询是否已被删除。

### 13. 执行查询时返回 "DataSource not found for Dataset X" 错误？

**解答**：这表示查询关联的数据集没有配置数据源，或数据源不存在。请确保数据集已正确配置数据源。

### 14. 执行查询时返回 "Query DSL is required for execution" 错误？

**解答**：这表示查询没有配置 DSL 定义。执行查询时必须提供 DSL 定义，用于生成 SQL 语句。

### 15. 执行查询时返回数据库连接错误？

**解答**：这可能是由于数据源配置错误导致的。请检查数据源的连接配置是否正确，包括主机、端口、用户名、密码等信息。

## 性能问题

### 16. 查询执行时间过长怎么办？

**解答**：查询执行时间过长可能由以下原因导致：
- 查询过于复杂：优化 DSL，减少不必要的维度和指标
- 数据量过大：添加适当的筛选条件，减少数据量
- 数据库索引缺失：确保数据库表有适当的索引
- 数据源性能问题：检查数据源服务器性能

### 17. 如何优化查询性能？

**解答**：优化查询性能的方法包括：
- 只选择必要的维度和指标
- 使用适当的筛选条件减少数据量
- 合理使用表连接，避免复杂的多表关联
- 对频繁执行的查询考虑结果缓存
- 监控查询执行时间，优化慢查询
- 定期检查和清理不再使用的查询

## 功能扩展

### 18. 如何添加新的指标类型？

**解答**：查询模块支持多种指标类型，包括聚合指标、行级指标、后聚合指标和算术指标。要添加新的指标类型，需要在数据集模块中定义新的指标，并确保 DSL 转换器支持该类型。

### 19. 如何支持新的数据库类型？

**解答**：要支持新的数据库类型，需要在数据源模块中添加对该数据库类型的支持，包括连接配置、SQL 生成等。

### 20. 如何实现查询结果缓存？

**解答**：查询结果缓存可以通过以下方式实现：
- 在查询执行后将结果存储到缓存中
- 下次执行相同查询时，先检查缓存是否存在有效结果
- 设置缓存过期时间，确保数据的新鲜度

## 权限和安全

### 21. 如何控制查询的访问权限？

**解答**：查询模块本身没有内置的权限控制机制，但可以通过以下方式实现：
- 在 API 网关层添加权限控制
- 在查询服务中添加用户认证和授权逻辑
- 基于查询的状态和属性设置访问权限

### 22. 如何保护敏感数据？

**解答**：保护敏感数据的方法包括：
- 数据源配置加密：使用加密存储数据源的连接信息
- 访问控制：限制对敏感查询的访问
- 数据脱敏：在返回结果前对敏感数据进行脱敏处理
- 审计日志：记录查询的执行情况，便于追踪

## 部署和维护

### 23. 如何监控查询执行情况？

**解答**：监控查询执行情况的方法包括：
- 记录查询执行时间和结果大小
- 监控查询失败率和错误类型
- 设置查询执行超时阈值
- 定期分析慢查询，进行优化

### 24. 如何备份查询定义？

**解答**：查询定义存储在数据库中，可以通过以下方式备份：
- 定期备份数据库
- 导出查询定义为 JSON 文件
- 使用版本控制系统管理查询定义

### 25. 如何迁移查询定义到新环境？

**解答**：迁移查询定义到新环境的方法包括：
- 从源环境导出查询定义
- 在目标环境导入查询定义
- 确保目标环境的数据集和数据源配置与源环境一致

## 其他问题

### 26. 查询模块与其他模块的关系是什么？

**解答**：查询模块与其他模块的关系：
- **数据集模块**：查询模块依赖数据集模块提供的数据集信息，包括表、字段、指标等
- **数据源模块**：查询模块依赖数据源模块提供的数据源配置和连接能力
- **metric-engine**：查询模块使用 metric-engine 进行 DSL 转换和 SQL 生成

### 27. 如何测试查询功能？

**解答**：测试查询功能的方法包括：
- 单元测试：测试 DSL 转换、SQL 生成等核心功能
- 集成测试：测试查询的完整执行流程
- 性能测试：测试查询在不同数据量下的性能
- 端到端测试：测试查询的整个生命周期

### 28. 如何调试查询执行过程？

**解答**：调试查询执行过程的方法包括：
- 查看生成的 SQL 语句
- 检查执行时间和结果
- 开启详细日志，记录执行过程
- 使用数据库工具执行生成的 SQL，分析执行计划

### 29. 如何处理查询结果的分页？

**解答**：查询模块目前不直接支持结果分页，但可以通过以下方式实现：
- 在 DSL 中添加分页相关的筛选条件
- 在执行查询后对结果进行客户端分页
- 扩展查询模块，添加分页支持

### 30. 如何实现定时执行查询？

**解答**：实现定时执行查询的方法包括：
- 使用外部调度系统，如 cron 或任务调度服务
- 扩展查询模块，添加调度功能
- 定期调用执行查询的 API 接口

# Dashboard 模块核心业务逻辑文档

## 1. 模块概述

Dashboard 模块是一个用于创建、管理和展示仪表盘的功能模块，支持添加不同类型的面板（如图表、表格、文本和卡片），并可以自定义仪表盘布局。布局支持响应式设计，适配不同屏幕尺寸。

### 1.1 核心功能

- 仪表盘管理：创建、查询、更新、删除仪表盘
- 面板管理：创建、查询、更新、删除面板
- 布局管理：更新仪表盘布局（支持响应式断点）
- 面板关联：向仪表盘添加或移除面板
- 布局验证：验证布局中的面板 ID 是否有效

### 1.2 模块依赖

- TypeOrmModule：用于数据库操作
- QueryModule：用于关联查询数据

## 2. 核心业务流程

### 2.1 仪表盘管理流程

#### 创建仪表盘

1. 接收创建仪表盘请求（名称和布局）
2. 验证请求参数
3. **验证布局中的面板 ID 是否存在**（新增）
4. 创建仪表盘实体
5. 保存到数据库
6. 返回创建结果

#### 查询仪表盘

1. 接收查询请求（单个或所有）
2. 从数据库查询仪表盘数据
3. 对于单个查询，加载关联的面板数据
4. 转换为响应格式
5. 返回查询结果

#### 更新仪表盘

1. 接收更新请求（ID 和更新数据）
2. 验证请求参数
3. 从数据库查询仪表盘
4. 更新仪表盘数据
5. 保存到数据库
6. 返回更新结果

#### 删除仪表盘

1. 接收删除请求（ID）
2. 从数据库删除仪表盘
3. 级联删除关联的面板关系
4. 返回删除结果

### 2.2 面板管理流程

#### 创建面板

1. 接收创建面板请求（标题、类型、查询 ID、配置、宽高）
2. 验证请求参数
3. 创建面板实体
4. 保存到数据库
5. 返回创建结果

#### 查询面板

1. 接收查询请求（单个或所有）
2. 从数据库查询面板数据
3. 转换为响应格式
4. 返回查询结果

#### 更新面板

1. 接收更新请求（ID 和更新数据）
2. 验证请求参数
3. 从数据库查询面板
4. 更新面板数据
5. 保存到数据库
6. 返回更新结果

#### 删除面板

1. 接收删除请求（ID）
2. 从数据库删除面板
3. 级联删除关联的仪表盘关系
4. 返回删除结果

### 2.3 面板关联流程

#### 添加面板到仪表盘

1. 接收添加请求（仪表盘 ID 和面板 ID）
2. 验证请求参数
3. 创建面板关系实体
4. 保存到数据库
5. 返回添加结果

#### 从仪表盘移除面板

1. 接收移除请求（仪表盘 ID 和面板 ID）
2. 验证请求参数
3. 从数据库删除面板关系
4. 返回移除结果

### 2.4 布局更新流程

1. 接收布局更新请求（仪表盘 ID 和布局数据）
2. 验证请求参数
3. **验证布局中的面板 ID 是否存在**
4. 从数据库查询仪表盘
5. 更新布局数据
6. 保存到数据库
7. 返回更新结果

### 2.5 布局验证流程（新增）

1. 检查布局是否为空，为空则跳过验证
2. 遍历所有断点（lg、md、sm、xs、xxs）的布局项
3. 收集所有布局项中的面板 ID（`i` 字段）
4. 查询所有已存在的面板
5. 比对布局中的面板 ID 是否都在已存在的面板列表中
6. 如果存在无效的面板 ID，抛出 `BadRequestException` 异常

## 3. 业务规则

### 3.1 数据验证规则

- 仪表盘名称：必填，字符串类型
- 仪表盘布局：可选，JSON 格式（响应式布局结构）
- 面板标题：可选，字符串类型
- 面板类型：必填，枚举类型（chart、table、text、card）
- 面板查询 ID：可选，UUID 格式
- 面板配置：可选，JSON 格式
- 面板宽高：可选，数字类型

### 3.2 布局验证规则（新增）

- 布局中的面板 ID（`i` 字段）必须对应已存在的面板
- 布局支持五个响应式断点：lg、md、sm、xs、xxs
- 每个布局项必须包含：`i`（面板 ID）、`x`（水平位置）、`y`（垂直位置）、`w`（宽度）、`h`（高度）
- 布局项可选包含：`minW`、`minH`、`maxW`、`maxH`、`static`、`isDraggable`、`isResizable`

### 3.3 业务约束

- 一个仪表盘可以包含多个面板
- 一个面板可以被多个仪表盘使用
- 面板类型必须是预定义的枚举值
- 查询 ID 必须对应存在的查询
- 布局中的面板 ID 必须对应存在的面板

### 3.4 异常处理规则

- 资源不存在：返回 404 错误
- 参数验证失败：返回 400 错误
- 布局中包含无效面板 ID：返回 400 错误
- 服务器内部错误：返回 500 错误

## 4. 服务层逻辑

### 4.1 DashboardService

- **create**：创建仪表盘（包含布局验证）
- **findAll**：查询所有仪表盘
- **findOne**：查询单个仪表盘（包含关联面板）
- **update**：更新仪表盘
- **remove**：删除仪表盘
- **updateLayout**：更新仪表盘布局（包含布局验证）
- **addPanel**：向仪表盘添加面板
- **removePanel**：从仪表盘移除面板
- **validateLayoutPanelIds**：验证布局中的面板 ID 是否有效（私有方法）

### 4.2 PanelService

- **create**：创建面板
- **findAll**：查询所有面板
- **findOne**：查询单个面板
- **update**：更新面板
- **remove**：删除面板

## 5. 控制器层逻辑

### 5.1 DashboardController

- **POST /dashboard**：创建仪表盘
- **GET /dashboard**：获取所有仪表盘
- **GET /dashboard/:id**：获取单个仪表盘
- **PATCH /dashboard/:id**：更新仪表盘
- **DELETE /dashboard/:id**：删除仪表盘
- **PUT /dashboard/:id/layout**：更新仪表盘布局
- **POST /dashboard/:id/panels**：向仪表盘添加面板
- **DELETE /dashboard/:id/panels/:panelId**：从仪表盘移除面板

### 5.2 PanelController

- **POST /panel**：创建面板
- **GET /panel**：获取所有面板
- **GET /panel/:id**：获取单个面板
- **PATCH /panel/:id**：更新面板
- **DELETE /panel/:id**：删除面板

## 6. 数据处理流程

### 6.1 数据存储

- 仪表盘数据存储在 `dashboard` 表
- 面板数据存储在 `panel` 表
- 仪表盘与面板的关联关系存储在 `dashboard_panels` 表

### 6.2 数据转换

- 请求数据：DTO → 实体
- 响应数据：实体 → 响应 DTO

### 6.3 事务处理

- 所有数据库操作都在事务中执行
- 级联操作：删除仪表盘时级联删除关联的面板关系
- 级联操作：删除面板时级联删除关联的仪表盘关系

## 7. 异常处理

### 7.1 常见异常

- **NotFoundException**：资源不存在
  - 仪表盘不存在
  - 面板不存在
  - 面板不在仪表盘中

- **BadRequestException**：请求参数错误
  - 缺少必填参数
  - 参数格式错误
  - 参数值无效
  - **布局中包含无效的面板 ID**（新增）

### 7.2 异常处理流程

1. 捕获异常
2. 记录错误日志
3. 返回适当的 HTTP 状态码和错误信息

## 8. 与其他模块的交互

### 8.1 与 Query 模块的交互

- 面板可以关联 Query 模块中的查询
- 关联方式：通过 `queryId` 字段
- 交互目的：面板展示查询结果数据

### 8.2 与其他模块的潜在交互

- **用户模块**：可以添加用户权限控制，限制仪表盘和面板的访问
- **权限模块**：可以添加基于角色的访问控制
- **缓存模块**：可以添加缓存机制，提高面板数据加载速度

## 9. 性能优化

### 9.1 数据库优化

- 使用索引加速查询
- 合理设计表结构
- 避免不必要的关联查询

### 9.2 代码优化

- 使用异步操作
- 合理使用缓存
- 优化查询语句

### 9.3 前端优化

- 懒加载面板数据
- 分页加载大量数据
- 减少不必要的请求
- 响应式布局减少重排重绘

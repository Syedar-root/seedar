# 数据源模块常见问题解答

## 1. 配置相关问题

### 1.1 数据源配置验证失败

**问题**：创建或更新数据源时，配置验证失败。

**原因**：
- 配置参数不完整或格式错误
- 数据源类型与配置不匹配
- 缺少必要的配置字段

**解决方案**：
- 检查配置参数是否完整，确保所有必填字段都已提供
- 验证数据源类型与配置结构是否匹配
- 参考 API 文档中的配置示例，确保格式正确
- 检查网络连接是否正常

**示例**：
```json
// MySQL 配置示例
{
  "name": "测试MySQL数据源",
  "type": "mysql",
  "config": {
    "host": "localhost",
    "port": "3306",
    "database": "test_db",
    "username": "root",
    "password": "123456"
  }
}
```

### 1.2 配置加密失败

**问题**：配置加密失败或解密失败。

**原因**：
- 环境变量 `ENCRYPTION_KEY` 未设置或值不正确
- 配置格式错误，无法正确加密
- 加密算法实现有问题

**解决方案**：
- 确保环境变量 `ENCRYPTION_KEY` 已正确设置
- 验证配置格式是否正确，特别是敏感信息字段
- 检查加密算法实现是否正确
- 查看日志获取详细错误信息

### 1.3 连接测试失败

**问题**：创建或更新数据源时，连接测试失败。

**原因**：
- 数据库服务未运行
- 连接配置错误（主机、端口、用户名、密码等）
- 网络连接问题
- 数据库用户权限不足

**解决方案**：
- 检查数据库服务是否正常运行
- 验证连接配置是否正确，特别是主机、端口、用户名和密码
- 确保网络连接畅通，防火墙未阻止连接
- 检查数据库用户是否有足够的权限
- 尝试使用命令行工具测试连接，如 `mysql -h host -u user -p`

## 2. 元数据相关问题

### 2.1 元数据获取失败

**问题**：数据源创建成功，但元数据获取失败。

**原因**：
- 数据库用户没有查询系统表的权限
- 数据库结构异常
- 数据源类型不支持元数据获取
- 网络连接中断

**解决方案**：
- 检查数据库用户是否有查询系统表的权限
- 验证数据库结构是否正常
- 确认数据源类型是否支持元数据获取
- 检查网络连接是否稳定
- 查看日志获取详细错误信息

### 2.2 表结构获取不完整

**问题**：元数据获取成功，但表结构不完整或有误。

**原因**：
- 数据库用户权限不足
- 数据库版本与代码兼容性问题
- 表结构复杂，超出处理能力

**解决方案**：
- 确保数据库用户有足够的权限查询表结构
- 检查数据库版本是否与代码兼容
- 对于复杂表结构，考虑分批处理
- 查看日志获取详细错误信息

### 2.3 外键关系获取失败

**问题**：表结构获取成功，但外键关系获取失败。

**原因**：
- 数据库不支持外键关系查询
- 数据库用户权限不足
- 外键关系复杂，超出处理能力

**解决方案**：
- 确认数据库类型是否支持外键关系查询（如 ClickHouse 原生不支持）
- 确保数据库用户有足够的权限查询外键关系
- 对于复杂外键关系，考虑分批处理
- 外键关系获取失败不影响数据源的基本功能，仅作为参考信息

## 3. 操作相关问题

### 3.1 数据源创建失败

**问题**：创建数据源时失败。

**原因**：
- 配置验证失败
- 连接测试失败
- 数据库操作失败
- 元数据获取失败

**解决方案**：
- 检查配置是否正确
- 验证数据库连接是否正常
- 查看日志获取详细错误信息
- 尝试简化配置，逐步排查问题

### 3.2 数据源更新失败

**问题**：更新数据源时失败。

**原因**：
- 数据源不存在
- 配置验证失败
- 连接测试失败
- 数据库操作失败

**解决方案**：
- 确认数据源 ID 是否正确
- 检查更新的配置是否有效
- 验证数据库连接是否正常
- 查看日志获取详细错误信息

### 3.3 数据源删除失败

**问题**：删除数据源时失败。

**原因**：
- 数据源不存在
- 数据库操作失败
- 存在关联的数据集或其他资源

**解决方案**：
- 确认数据源 ID 是否正确
- 检查是否存在关联的数据集或其他资源
- 查看日志获取详细错误信息
- 尝试使用软删除方式，即使失败也不会影响系统稳定性

## 4. 性能相关问题

### 4.1 元数据获取缓慢

**问题**：元数据获取过程缓慢，影响用户体验。

**原因**：
- 数据库表数量过多
- 表结构复杂
- 网络连接速度慢
- 数据库性能问题

**解决方案**：
- 优化数据库性能，确保系统表查询速度
- 考虑增加元数据缓存机制
- 对于大型数据库，考虑分批获取元数据
- 优化网络连接，减少延迟

### 4.2 连接池耗尽

**问题**：数据库连接池耗尽，导致操作失败。

**原因**：
- 连接池配置不合理
- 并发操作过多
- 连接未正确释放

**解决方案**：
- 合理配置连接池大小，根据实际需求调整
- 确保所有数据库操作后正确释放连接
- 实现连接超时机制，避免连接长时间占用
- 监控连接池使用情况，及时调整配置

### 4.3 配置加密解密性能问题

**问题**：配置加密解密过程缓慢，影响操作速度。

**原因**：
- 加密算法复杂度高
- 配置数据量大
- 加密密钥管理不当

**解决方案**：
- 选择合适的加密算法，平衡安全性和性能
- 只对敏感信息进行加密，减少加密数据量
- 实现配置缓存机制，减少重复加密解密操作
- 优化加密密钥管理，提高密钥访问速度

## 5. 安全相关问题

### 5.1 敏感信息泄露

**问题**：数据源配置中的敏感信息（如密码）可能泄露。

**原因**：
- 配置未加密存储
- 日志中记录了敏感信息
- API 响应中包含敏感信息

**解决方案**：
- 确保配置中的敏感信息已加密存储
- 配置日志系统，避免记录敏感信息
- 检查 API 响应，确保敏感信息已适当处理
- 实现数据脱敏机制，在展示时隐藏敏感信息

### 5.2 权限控制不足

**问题**：数据源访问权限控制不足，可能导致未授权访问。

**原因**：
- 缺少权限验证机制
- 权限配置不当
- 接口未进行权限检查

**解决方案**：
- 实现数据源访问权限控制机制
- 为不同用户角色设置适当的权限
- 在所有数据源操作接口中添加权限检查
- 定期审计权限配置，确保安全性

### 5.3 SQL 注入风险

**问题**：使用数据源时存在 SQL 注入风险。

**原因**：
- 直接拼接 SQL 语句
- 未使用参数化查询
- 输入验证不足

**解决方案**：
- 使用 ORM 框架的参数化查询
- 避免直接拼接 SQL 语句
- 对所有用户输入进行严格验证
- 实施最小权限原则，限制数据库用户权限

## 6. 其他常见问题

### 6.1 数据源类型不支持

**问题**：尝试使用不支持的数据源类型。

**原因**：
- 数据源类型未在 `DataSourceType` 枚举中定义
- 代码未实现该类型的处理逻辑

**解决方案**：
- 检查 `DataSourceType` 枚举，确认支持的数据源类型
- 如需添加新类型，按照文档中的步骤进行扩展
- 确保代码实现了对应类型的处理逻辑

### 6.2 时区问题

**问题**：数据源中的时间数据时区处理不当。

**原因**：
- 数据库时区与应用时区不一致
- 时间数据存储格式不正确
- 时间转换逻辑有误

**解决方案**：
- 统一数据库和应用的时区设置
- 使用 UTC 时间存储，避免时区混淆
- 确保时间转换逻辑正确处理时区差异
- 参考 `README-time-handling.md` 文件中的时间处理指南

### 6.3 版本兼容性问题

**问题**：数据源模块与其他模块或依赖库版本不兼容。

**原因**：
- 依赖库版本冲突
- API 接口变更
- 数据库驱动版本不兼容

**解决方案**：
- 确保所有依赖库版本兼容
- 定期更新依赖库，保持版本同步
- 测试不同版本组合，确保兼容性
- 参考项目的依赖版本要求

## 7. 故障排除指南

### 7.1 日志分析

**步骤**：
1. 查看应用日志，寻找错误信息
2. 关注与数据源相关的日志条目
3. 分析错误栈信息，定位问题根源
4. 根据错误信息采取相应措施

**常见日志关键词**：
- `ConfigValidationError`：配置验证错误
- `ConnectionTestFailed`：连接测试失败
- `SaveTablesAndColumnsError`：保存表和列信息失败
- `DatasourceNotFound`：数据源未找到

### 7.2 连接测试

**步骤**：
1. 使用命令行工具测试数据库连接
2. 验证网络连接是否正常
3. 检查数据库服务状态
4. 确认数据库用户权限

**示例命令**：
- MySQL：`mysql -h host -u user -p`
- PostgreSQL：`psql -h host -U user -d database`
- ClickHouse：`clickhouse-client --host=host --user=user --password=password`

### 7.3 配置验证

**步骤**：
1. 验证配置格式是否正确
2. 检查必填字段是否完整
3. 确认数据源类型与配置匹配
4. 测试配置的有效性

**工具**：
- 使用 JSON 验证工具检查配置格式
- 参考 API 文档中的配置示例
- 使用 `validateDataSourceConfig` 函数验证配置

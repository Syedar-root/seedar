## 三、维护规范

### 更新流程

1. 新增问题：需验证问题高频性（近 1 个月内出现 ≥3 次），解决方案需经过实际验证可落地；
2. 修改内容：更新后需标注“更新说明”和“更新人+日期”，确保追溯性；
3. 废弃问题：问题无实际使用场景后，移入“历史问题归档”模块，保留记录不直接删除。

### 审核标准

1. 问题描述：简洁无歧义，不使用专业术语（需解释的除外）；
2. 解决方案：步骤清晰、可直接操作，适配项目当前版本；
3. 操作示例：完整可运行，覆盖核心场景；
4. 相关链接：有效、权威，优先选择官方文档。

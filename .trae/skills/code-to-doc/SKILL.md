# Code-to-Doc 文档生成技能

此技能帮助你将项目或模块的代码自动转换为各种类型的文档，帮助新人快速理解和使用系统。

## 技能特点

- **渐进式加载**：每个文档类型都有独立的规范文件，按需加载
- **面向新人**：所有文档都以新人为目标读者
- **实用导向**：提供可操作的步骤和示例
- **避免技术细节**：不包含代码实现、数据库连接等技术细节
- **目标明确**：确保新人在 30 分钟内能够达到文档目标
- **灵活适配**：通过功能特征识别核心信息，适配不同语言/命名规范的项目

## 支持范围

### 项目类型

- Web 应用：有 HTTP 服务、Web 界面
- API 服务：提供 RESTful/GraphQL API
- CLI 工具：命令行界面
- 库/SDK：供其他代码调用的库
- 桌面应用：GUI 应用
- 移动应用：iOS/Android 应用

### 编程语言

- 主流通用语言：JavaScript/TypeScript（Node.js、React、Vue、Angular）、Python（Django、Flask、FastAPI）、Java（Spring Boot、Jakarta EE）、Go（Gin、Echo、Fiber）、Rust（Actix、Rocket、Axum）、C#（ASP.NET Core）、PHP（Laravel、Symfony）、Ruby（Rails、Sinatra）
- 适配逻辑：不依赖固定语法/命名，通过“功能特征”识别核心代码逻辑

### 业务领域

- 电商系统、社交平台、数据分析平台、内容管理系统、项目管理工具、客户关系管理、在线教育平台、医疗健康系统、金融理财系统、物流运输系统
- 通用适配：可延伸至各类业务场景，聚焦“核心实体-流程-规则”提取业务信息

## 任务执行模式（Plan + Subagent）

### 核心逻辑

1. **主 Agent（Plan 层）**：接收用户需求后，先制定整体执行计划，拆分出若干子任务；
2. **子 Agent（执行层）**：每个子任务分配专属 Subagent，按专业分工完成单一类型文档的生成；
3. **主 Agent（整合层）**：汇总所有 Subagent 的产出，校验格式/逻辑一致性后输出最终报告。

### 任务拆分规则

| 主任务（文档生成） | 子任务（Subagent 分工）                                                                                    |
| ------------------ | ---------------------------------------------------------------------------------------------------------- |
| 多类型文档批量生成 | Subagent 1：API 文档生成<br>Subagent 2：快速入门指南生成<br>Subagent 3：数据模型文档生成<br>（依需求扩展） |
| 单一类型文档生成   | Subagent：聚焦该类型文档的“特征识别 → 信息提取 → 规范生成”全流程                                           |

## 使用流程

### 第一步：需求解析与计划制定

- 主 Agent 解析用户需求，明确文档类型、覆盖范围（全项目/特定模块）；
  - 若用户需求为泛化指令（如“总结模块”“生成文档”“帮助新人理解模块”），默认触发「多类型文档批量生成」模式，自动拆分以下核心子任务：
    - Subagent 1：API 文档（若模块含接口）
    - Subagent 2：快速入门指南
    - Subagent 3：核心业务逻辑文档
    - Subagent 4：数据模型文档（若模块含数据实体）
    - Subagent 5：FAQ 文档
    - Subagent 6：PRD 文档（默认生成，聚焦核心业务目标 / 边界）
    - Subagent X：其他等文档
- 制定执行计划，拆分出子任务清单（明确每个 Subagent 的分工、输出标准、时间节点）。

### 第二步：识别项目通用特征

- 识别核心特征：项目类型（Web/API/CLI 等）、核心业务领域、数据存储方式；
- 跳过语言/命名依赖：不绑定特定文件命名/后缀，以“功能特征”为核心识别逻辑。

### 第三步：加载对应规范

根据文档类型，加载`references/`目录下对应的规范文件：

- API 文档：`references/api-doc.md`
- 快速入门指南：`references/quick-start.md`
- 核心业务逻辑文档：`references/business-logic.md`
- 数据模型文档：`references/data-model.md`
- FAQ 文档：`references/faq.md`
- PRD 文档：`references/prd.md`

### 第四步：Subagent 执行代码分析

主 Agent 将“代码分析+文档生成”任务分发至对应 Subagent，各 Subagent 按以下**通用特征规则**分析代码（避免语言/命名依赖）：

#### API 文档分析规则（通用特征）

- 识别“接口入口特征”：路由定义、请求方法（GET/POST/PUT/DELETE）、参数校验、响应格式定义；
- 识别“接口关联逻辑”：权限校验、业务逻辑调用、异常返回；
- 适配逻辑：不依赖`controller/route/api`等固定命名，聚焦“请求-响应”核心特征。

#### 快速入门指南分析规则（通用特征）

- 识别“环境配置特征”：依赖管理文件、环境变量定义、启动脚本、数据库初始化逻辑；
- 识别“运行流程特征”：项目启动入口、核心配置加载顺序、依赖安装命令；
- 适配逻辑：不绑定`package.json/requirements.txt`等固定文件，聚焦“依赖-配置-启动”核心流程。

#### 核心业务逻辑文档分析规则（通用特征）

- 识别“业务流程特征”：核心操作（创建/修改/删除）、规则校验、状态流转、上下游依赖；
- 识别“业务规则特征”：权限控制、数据校验、计算逻辑、异常处理；
- 适配逻辑：不依赖`service/business/logic`等固定命名，聚焦“业务操作-规则-流转”核心逻辑。

#### 数据模型文档分析规则（通用特征）

- 识别“数据实体特征”：字段定义、主键/外键、数据类型、约束规则；
- 识别“实体关系特征”：一对一/一对多/多对多关联、关联查询逻辑；
- 适配逻辑：不绑定 ORM 框架特定文件，聚焦“实体-字段-关系”核心特征。

#### FAQ 文档分析规则（通用特征）

- 识别“异常处理特征”：错误码、异常提示、容错逻辑；
- 识别“高频问题特征”：注释中的 TODO/FIXME、测试用例中的失败场景、配置校验失败逻辑；
- 适配逻辑：不依赖`exception/error/validation`等固定命名，聚焦“异常场景-解决方案”核心特征。

#### PRD 文档分析规则（通用特征）

- 识别“业务目标特征”：注释中的业务描述、配置中的权限/角色定义、接口中的业务参数；
- 识别“业务边界特征”：功能开关、权限范围、数据访问限制；
- 适配逻辑：不绑定`business/prd/requirements`等固定文件，聚焦“业务目标-规则-边界”核心特征。

### 第五步：Subagent 生成文档

各 Subagent 按规范生成对应文档，确保：

- 符合“面向新人、简洁明了、实用导向”原则；
- 不包含语言/框架特定技术细节；
- 统一使用通用类型名称（string/number/boolean 等）。

### 第六步：主 Agent 整合与输出

- 主 Agent 校验所有 Subagent 产出的格式、逻辑一致性；
- 输出规则（优先级：用户指定 > 默认规则）：
  1. 不直接在对话界面输出完整文档内容，仅输出「文档生成清单」；
  2. 自动为每种类型的文档创建独立的 MD 文件，文件命名规范：
     - API 文档：`{模块名}-api-doc.md`
     - 快速入门指南：`{模块名}-quick-start.md`
     - 核心业务逻辑文档：`{模块名}-business-logic.md`
     - 数据模型文档：`{模块名}-data-model.md`
     - FAQ 文档：`{模块名}-faq.md`
     - PRD 文档：`{模块名}-prd.md`
  3. 文件存储路径：
     - 若用户指定了模块路径 / 覆盖范围为 “特定模块”：输出至 {模块所在目录}/docs/（自动创建该目录）；
     - 若覆盖范围为 “全项目”：输出至当前工作目录下的 docs/；
     - 若未明确覆盖范围（泛化指令）：输出至 ./docs/modules/{模块名}/（自动创建 docs/modules/ 目录）；
     - 支持用户自定义路径：若用户需求中指定路径（如 “生成文档到 ./user/docs/”），则优先遵循用户指定路径。
  4. 在对话界面仅展示「生成完成提示」+「文件清单」+「关键内容摘要」，示例：
     > 已为「用户模块」生成以下文档（存储路径：./docs/）：
     >
     > 1. user-module-api-doc.md（包含 8 个核心接口）
     > 2. user-module-quick-start.md（含环境配置、启动步骤）
     > 3. user-module-business-logic.md（核心流程：用户注册 → 登录 → 权限校验）
     > 4. user-module-data-model.md（含 User/Role 2 个核心实体）
     > 5. user-module-faq.md（覆盖 10 个高频异常场景）
     > 6. user-module-prd.md（业务目标：用户注册、登录、权限校验）

## 触发条件

当用户提出以下需求时，应立即调用此技能：

- 精准指令："生成 API 文档" "写一个快速入门指南" ...（原有内容）
- 泛化指令："总结这个模块" "生成文档" "帮助新人理解这个模块" "从代码生成文档"
  → 触发规则：默认按「多类型文档批量生成」模式执行，自动生成 API 文档、快速入门指南、业务逻辑文档、数据模型文档、FAQ 文档（按需），并输出为独立 MD 文件。

## 文档生成原则

所有生成的文档必须遵循以下原则：

- **面向新人**：假设读者是刚接触项目的新人
- **简洁明了**：避免冗长的描述，直接给出核心信息
- **实用导向**：提供可操作的步骤和示例
- **避免技术细节**：不包含代码实现、数据库连接等技术细节
- **目标明确**：确保新人在 30 分钟内能够达到文档目标
- **类型友好**：使用通用的类型名称（string、number、boolean 等）
- **避免术语**：避免使用项目内部术语或技术术语，或提供解释

## 注意事项

- 文档应使用中文编写（除非用户指定其他语言）
- 代码示例应完整可运行
- 避免使用项目内部术语，或提供解释
- 保持文档结构清晰，使用适当的标题层级
- 流程图使用 Mermaid 格式
- ER 图使用 Mermaid 格式
- 根据项目类型选择合适的文档格式
- 根据编程语言选择合适的代码示例
- 根据业务领域选择合适的业务术语
- 定期更新文档，保持与代码同步
- 输出形态：优先生成独立 MD 文件（存储至 ./docs/ 目录），对话界面仅展示生成清单和核心摘要，不输出完整文档内容；
- 文件兼容性：MD 文件遵循 CommonMark 规范，支持主流编辑器/文档工具渲染；
- 批量生成：泛化指令默认生成至少 3 类核心文档（快速入门、业务逻辑、FAQ），含接口/数据的模块额外生成 API/数据模型文档。

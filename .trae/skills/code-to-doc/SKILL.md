# Code-to-Doc 文档生成与更新技能

此技能帮助你将项目或模块的代码自动转换为各种类型的文档 或 因代码迭代/反馈问题更新文档，帮助新人快速理解和使用系统并保持文档与代码的实时同步。

## 技能特点

- **面向新人**：所有文档都以新人为目标读者
- **实用导向**：提供可操作的步骤和示例
- **避免技术细节**：不包含代码实现、数据库连接等技术细节
- **目标明确**：确保新人在 30 分钟内能够达到文档目标
- **灵活适配**：通过功能特征识别核心信息，适配不同语言/命名规范的项目
- **增量更新优先**：支持根据代码变更/文档反馈精准更新，而非全量重建，保障信息延续性

## 支持范围

### 项目类型

- Web 应用：有 HTTP 服务、Web 界面
- API 服务：提供 RESTful/GraphQL API
- CLI 工具：命令行界面
- 库/SDK：供其他代码调用的库
- 桌面应用：GUI 应用
- 移动应用：iOS/Android 应用

### 编程语言

- 主流通用语言：JavaScript/TypeScript（Node.js、React、Vue、Angular）、Python（Django、Flask、FastAPI）、Java（Spring Boot、Jakarta EE）、Go（Gin、Echo、Fiber）、Rust（Actix、Rocket、Axum）、C#（ASP.NET Core）、PHP（Laravel、Symfony）、Ruby（Rails、Sinatra）
- 适配逻辑：不依赖固定语法/命名，通过“功能特征”识别核心代码逻辑

### 业务领域

- 电商系统、社交平台、数据分析平台、内容管理系统、项目管理工具、客户关系管理、在线教育平台、医疗健康系统、金融理财系统、物流运输系统
- 通用适配：可延伸至各类业务场景，聚焦“核心实体-流程-规则”提取业务信息

### 文档更新支持体系

#### 触发场景（更新类）

| 触发场景                   | 核心识别逻辑                                                                |
| -------------------------- | --------------------------------------------------------------------------- |
| 代码变更（新增/修改/删除） | 对比变更前后代码，识别“新增逻辑/修改逻辑/废弃逻辑”，定位需更新的文档模块    |
| 文档过期反馈               | 识别用户反馈的“文档与代码不一致”点，定位至具体文档章节/字段                 |
| 新人使用反馈               | 识别新人提问中“文档未覆盖/文档描述错误”的内容，标记为文档待更新项           |
| 定期同步检查               | 按“模块/项目”粒度扫描文档与代码的一致性，输出待更新清单（无主动反馈时触发） |

#### 代码变更类型与更新策略

| 代码变更类型               | 文档更新策略                                                                  |
| -------------------------- | ----------------------------------------------------------------------------- |
| 功能新增（接口/实体/流程） | 增量新增文档章节：补充至对应文档（API/数据模型/业务逻辑），不改动原有内容     |
| 功能修改（逻辑/参数/规则） | 增量修改文档：仅更新变更部分的描述，保留历史正确内容，标注“更新时间+变更点”   |
| 功能删除（接口/实体/流程） | 增量标记文档：标注该部分“已废弃”+ 废弃原因+替代方案，非核心删除不直接删除内容 |
| 异常逻辑调整               | 仅更新 FAQ/业务逻辑文档中对应异常场景，补充新的异常处理说明                   |
| 配置/环境调整              | 仅更新快速入门指南中环境配置章节，同步最新配置要求                            |

## 任务执行模式（Plan + Subagent）

### 核心逻辑

1. **主 Agent（Plan 层）**：接收用户需求后，先制定整体执行计划，拆分出若干子任务；
2. **子 Agent（执行层）**：每个子任务分配专属 Subagent，按专业分工完成单一类型文档的生成/更新；
3. **主 Agent（整合层）**：汇总所有 Subagent 的产出，校验格式/逻辑一致性后输出最终报告。

### 任务拆分规则（按代码粒度动态匹配）

#### 文档生成任务拆分（原有逻辑）

| 代码粒度   | 主任务（文档生成）             | 子任务（Subagent 分工）                                                                                                                                                                                                                                                |
| ---------- | ------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 代码片段   | 轻量化文档生成                 | Subagent 1：核心逻辑极简说明<br>Subagent 2：极简 FAQ（仅覆盖片段异常）                                                                                                                                                                                                 |
| 单文件代码 | 轻量化文档生成                 | Subagent 1：单文件功能说明<br>Subagent 2：极简 FAQ（仅覆盖文件异常）<br>Subagent X（可选）：单接口/单实体极简说明（含接口/数据时触发）                                                                                                                                 |
| 模块代码   | 多类型文档批量生成（原有逻辑） | Subagent 1：API 文档（含接口时）<br>Subagent 2：快速入门指南<br>Subagent 3：核心业务逻辑文档<br>Subagent 4：数据模型文档（含数据实体时）<br>Subagent 5：FAQ 文档<br>Subagent 6：PRD 文档（核心模块时）                                                                 |
| 项目代码   | 项目级整合文档生成             | Subagent 1：API 总览文档（复用模块 API+全局规则）<br>Subagent 2：项目级快速入门<br>Subagent 3：项目级业务逻辑（模块交互+全局流程）<br>Subagent 4：数据模型总览文档（复用模块数据+全局关系）<br>Subagent 5：项目级 FAQ<br>Subagent 6：PRD 总览文档（项目目标+全局边界） |

#### 文档更新任务拆分（新增）

| 代码粒度   | 主任务（文档更新）     | 子任务（Subagent 分工）                                                                                                                                                                                                                                                                                                                            |
| ---------- | ---------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 代码片段   | 片段级文档增量修正     | Subagent 1：定位片段对应文档位置<br>Subagent 2：仅修正该片段相关的文档描述（核心逻辑/FAQ）<br>Subagent 3：校验修正后内容与代码一致性                                                                                                                                                                                                               |
| 单文件代码 | 文件级文档增量更新     | Subagent 1：定位文件对应文档章节<br>Subagent 2：更新文件功能说明/接口/实体描述（仅变更部分）<br>Subagent 3：更新文件相关 FAQ<br>Subagent 4：校验更新后内容完整性                                                                                                                                                                                   |
| 模块代码   | 模块级文档批量增量更新 | Subagent 1：更新 API 文档（仅变更接口）<br>Subagent 2：更新快速入门指南（仅变更运行/配置流程）<br>Subagent 3：更新核心业务逻辑（仅变更流程/规则）<br>Subagent 4：更新数据模型（仅变更实体/关系）<br>Subagent 5：更新 FAQ（仅变更异常）<br>Subagent 6：校验全模块文档一致性                                                                         |
| 项目代码   | 项目级文档整合更新     | Subagent 1：更新 API 总览（仅跨模块变更接口）<br>Subagent 2：更新项目快速入门（仅全局配置/启动流程）<br>Subagent 3：更新项目业务逻辑（仅模块交互/全局流程）<br>Subagent 4：更新数据模型总览（仅全局实体关系）<br>Subagent 5：更新项目 FAQ（仅全局/跨模块问题）<br>Subagent 6：更新 PRD 总览（仅全局目标/边界）<br>Subagent 7：校验全项目文档一致性 |

## 使用流程

### 第一步：需求解析与计划制定

- 主 Agent 解析用户需求，明确文档类型、覆盖范围；
- 核心判定逻辑：
  1. 识别需求类型（生成文档 / 更新文档）；
  2. 识别代码粒度（片段/单文件/模块/项目）；
  3. 识别代码特征（是否含接口/数据实体/环境配置/异常逻辑等）；
     - 若为「更新文档」需求：额外识别代码变更类型（新增/修改/删除）、更新触发源（代码变更/反馈/定期检查）；
  4. 生成「文档类型清单」（按粒度适配，非固定 6 类）：
     - 泛化指令（如“总结模块”“生成文档”）：按上表默认规则触发；
     - 精准指令（如“生成 API 文档”“更新 FAQ 文档”）：仅触发指定文档类型，且按粒度适配分析规则。
- 制定执行计划，拆分出子任务清单（明确每个 Subagent 的分工、输出标准、时间节点）。

### 第二步：识别项目通用特征

- 识别核心特征：项目类型（Web/API/CLI 等）、核心业务领域、数据存储方式；
- 跳过语言/命名依赖：不绑定特定文件命名/后缀，以“功能特征”为核心识别逻辑。

### 第三步：加载对应规范

根据文档类型，加载`references/`目录下对应的规范文件：

- API 文档：`references/api-doc.md`
- 快速入门指南：`references/quick-start.md`
- 核心业务逻辑文档：`references/business-logic.md`
- 数据模型文档：`references/data-model.md`
- FAQ 文档：`references/faq.md`
- PRD 文档：`references/prd.md`
- 文档更新通用规范：`references/doc-update.md`（新增）

### 第四步：Subagent 执行代码分析（生成场景）

主 Agent 将“代码分析+文档生成”任务分发至对应 Subagent，各 Subagent 按以下**通用特征规则**分析代码（避免语言/命名依赖）：

#### 通用规则（所有粒度）

不依赖固定命名/框架，聚焦“功能特征”核心逻辑，避免技术细节。

#### 粒度差异化分析规则

| 代码粒度   | API 文档分析规则                        | 快速入门指南分析规则           | 核心业务逻辑分析规则                    | 数据模型分析规则                 | FAQ 分析规则                        | PRD 分析规则                          |
| ---------- | --------------------------------------- | ------------------------------ | --------------------------------------- | -------------------------------- | ----------------------------------- | ------------------------------------- |
| 代码片段   | 跳过                                    | 跳过                           | 仅分析“输入 → 处理 → 输出”单一逻辑      | 跳过                             | 仅分析片段异常                      | 跳过                                  |
| 单文件代码 | 仅分析单接口特征（含接口时）            | 跳过                           | 仅分析文件级单一功能                    | 仅分析单实体特征（含数据时）     | 仅分析文件相关异常                  | 跳过                                  |
| 模块代码   | 原有规则（接口入口+关联逻辑）           | 原有规则（环境+运行流程）      | 原有规则（业务流程+规则）               | 原有规则（实体+关系）            | 原有规则（异常+高频问题）           | 原有规则（目标+边界）                 |
| 项目代码   | 弱化单接口细节，强化接口总览+跨模块交互 | 整合模块启动流程，强化全局配置 | 弱化单模块流程，强化模块间交互+全局流程 | 弱化单实体细节，强化实体全局关系 | 弱化单模块异常，强化全局/跨模块问题 | 弱化单模块目标，强化项目全局目标+边界 |

### 第五步：Subagent 执行文档更新（新增，更新场景）

> 仅当需求为「更新文档」时触发，跳过第四步（生成场景）

- 主 Agent 将“代码变更分析+文档更新”任务分发至对应 Subagent，核心执行逻辑：
  1. **定位更新位置**：按“文档类型-模块-章节”精准匹配代码变更对应的文档内容；
  2. **执行增量更新**：按「代码变更类型与更新策略」执行更新，不改动无关联内容；
  3. **标注更新痕迹**：在更新位置添加轻量化标记（如 `> 【更新于202X-XX-XX】：因XX功能修改，此处参数从A调整为B`）；
  4. **废弃内容处理**：功能删除时仅标注“已废弃”+ 废弃原因+替代方案，不直接删除文档内容。

### 第六步：Subagent 生成/更新文档

各 Subagent 按规范生成/更新对应文档，确保：

- 符合“面向新人、简洁明了、实用导向”原则；
- 不包含语言/框架特定技术细节；
- 统一使用通用类型名称（string/number/boolean 等）；
- 更新场景额外要求：仅增量修改，保留历史有效信息，标注更新痕迹。

### 第七步：主 Agent 整合与输出（粒度差异化输出）

- 主 Agent 校验所有 Subagent 产出的格式、逻辑一致性：
  - 生成场景：校验文档完整性、新人可读性；
  - 更新场景：校验“更新内容与代码一致性”“无冗余修改”“更新痕迹清晰”；
- 输出规则（优先级：用户指定 > 粒度默认规则）：

| 需求类型 | 代码粒度   | 输出形态     | 文件生成规则                                                      | 对话界面展示规则                                                 |
| -------- | ---------- | ------------ | ----------------------------------------------------------------- | ---------------------------------------------------------------- |
| 生成     | 代码片段   | 仅嵌入对话   | 不生成独立 MD 文件                                                | 直接展示“核心逻辑极简说明+极简 FAQ”完整内容（100 字内）          |
| 生成     | 单文件代码 | 仅嵌入对话   | 不生成独立 MD 文件                                                | 直接展示“单文件功能说明+可选单接口/实体说明”完整内容（300 字内） |
| 生成     | 模块代码   | 独立 MD 文件 | 原有规则：{模块名}-{文档类型}.md，存储至{模块目录}/docs/          | 原有规则：生成清单 + 关键内容摘要                                |
| 生成     | 项目代码   | 独立 MD 文件 | 调整规则：{项目名}-{文档类型}-overview.md，存储至项目根目录/docs/ | 调整规则：生成清单 + 复用链接 + 全局核心摘要                     |
| 更新     | 代码片段   | 仅嵌入对话   | 不生成独立 MD 文件                                                | 展示“更新点摘要+校验结果”（50 字内）                             |
| 更新     | 单文件代码 | 仅嵌入对话   | 不生成独立 MD 文件                                                | 展示“更新点摘要+校验结果”（100 字内）                            |
| 更新     | 模块代码   | 独立 MD 文件 | 覆盖原文件，新增「更新日志」章节                                  | 展示“更新文档清单+各文档更新点+校验结果”                         |
| 更新     | 项目代码   | 独立 MD 文件 | 覆盖原文件，新增「更新日志」章节                                  | 展示“更新文档清单+全局更新点+校验结果+回滚说明”                  |

- 输出示例（项目级更新）：
  > 已为「电商项目」更新以下文档（存储路径：./docs/）：
  >
  > 1. e-commerce-api-overview.md（更新点：用户支付接口参数调整，标注更新时间 202X-XX-XX）
  > 2. e-commerce-quick-start-overview.md（更新点：支付模块启动依赖新增 Redis 配置）
  > 3. e-commerce-faq-overview.md（更新点：补充“支付回调超时”新异常场景）
  >    校验结果：所有更新内容与代码逻辑一致，无冗余修改；若需回滚，可恢复至 docs/backup/202X-XX-XX/目录下版本。

## 触发条件

当用户提出以下需求时，应立即调用此技能：

### 文档生成类指令

- 精准指令："生成 API 文档" "写一个快速入门指南" ...（原有内容）
- 泛化指令："总结这个模块" "生成文档" "帮助新人理解这个模块" "从代码生成文档"
  → 触发规则：默认按「多类型文档批量生成」模式执行，自动生成 API 文档、快速入门指南、业务逻辑文档、数据模型文档、FAQ 文档（按需），并输出为独立 MD 文件。

### 文档更新类指令（新增）

- 精准指令："更新 API 文档" "根据代码变更更新文档" "修正快速入门指南的配置步骤" "标记废弃接口的文档" "同步支付模块文档与代码"
- 泛化指令："同步文档与代码" "更新模块文档" "修正文档错误" "检查文档是否过期" "更新新人手册"
  → 触发规则：默认按「文档更新任务拆分规则」执行，先识别代码变更/文档问题，再增量更新对应文档，输出更新报告；无明确代码范围时，默认扫描近 7 天变更的代码模块。

## 文档生成与更新原则（整合原有+新增）

所有生成/更新的文档必须遵循以下原则：

- **面向新人**：假设读者是刚接触项目的新人
- **简洁明了**：避免冗长的描述，直接给出核心信息
- **实用导向**：提供可操作的步骤和示例
- **避免技术细节**：不包含代码实现、数据库连接等技术细节
- **目标明确**：确保新人在 30 分钟内能够达到文档目标
- **类型友好**：使用通用的类型名称（string、number、boolean 等）
- **避免术语**：避免使用项目内部术语或技术术语，或提供解释
- **增量更新优先**：仅更新与代码变更/反馈问题相关的内容，不全量重建文档，保留历史有效信息
- **更新痕迹可追溯**：在更新位置标注更新时间、变更原因，便于后续追溯
- **废弃内容友好标注**：功能删除时不直接删除文档内容，仅标注“已废弃”+ 废弃原因+替代方案
- **更新后一致性**：确保更新后的文档与最新代码逻辑完全一致，无冲突/遗漏

## 注意事项

- 文档应使用中文编写（除非用户指定其他语言）
- 代码示例应完整可运行
- 避免使用项目内部术语，或提供解释
- 保持文档结构清晰，使用适当的标题层级
- 流程图使用 Mermaid 格式
- ER 图使用 Mermaid 格式
- 根据项目类型选择合适的文档格式
- 根据编程语言选择合适的代码示例
- 根据业务领域选择合适的业务术语
- 定期更新文档，保持与代码同步
- 输出形态：优先生成独立 MD 文件（存储至 ./docs/ 目录），对话界面仅展示生成/更新清单和核心摘要，不输出完整文档内容；
- 文件兼容性：MD 文件遵循 CommonMark 规范，支持主流编辑器/文档工具渲染；
- 批量生成：泛化指令默认生成至少 3 类核心文档（快速入门、业务逻辑、FAQ），含接口/数据的模块额外生成 API/数据模型文档；
- 文档更新优先级：核心流程/接口/数据模型文档优先更新，FAQ/PRD 文档按需更新（新增）；
- 更新日志：项目/模块级文档在末尾新增「更新日志」章节，记录每次更新的时间、内容、触发源（新增）；
- 批量更新限制：泛化的“同步文档”指令仅更新近 7 天代码变更对应的文档，避免无意义全量扫描（新增）；
- 回滚机制：更新后若校验失败（如与代码逻辑冲突），自动回滚至更新前版本，并输出冲突点说明（新增）；
- 反馈闭环：新人反馈的文档问题，更新后需在对话界面告知用户“已修正 XX 文档的 XX 问题”，形成闭环（新增）。

# 文档更新通用规范

## 文档定位

为`code-to-doc`技能的文档更新操作提供统一执行标准，确保更新后文档与代码一致、痕迹可追溯、内容无冗余，同时遵循「增量更新优先」原则，避免全量重建文档。

## 适用范围

所有通过`code-to-doc`技能执行的**模块/项目级文档更新**，覆盖 API、快速入门指南、核心业务逻辑、数据模型、FAQ、PRD 全文档类型。

## 核心更新原则

1. **增量更新**：仅修改/新增/标注与代码变更/反馈问题相关的内容，不改动无关联的历史有效内容；
2. **痕迹可追溯**：所有更新位置必须添加轻量化更新标记，废弃内容必须标注废弃信息；
3. **新人友好**：更新后仍保持文档简洁性，不引入技术细节，确保新人 30 分钟内可理解核心内容；
4. **一致性校验**：更新后必须完成「代码逻辑-文档描述」「各文档间关联内容」两层一致性校验；
5. **内容不删除**：功能/接口/实体删除时，不直接删除文档内容，仅做废弃标注，保留历史参考价值。

## 通用更新流程

1. **定位匹配**：按「文档类型 → 模块/项目 → 章节/小节 → 具体内容」的层级，精准匹配代码变更/反馈问题对应的文档位置；
2. **增量更新**：严格遵循《代码变更与文档更新映射规则》执行修改/新增/标注操作；
3. **标记规范**：在更新/废弃位置添加标准化更新标记；
4. **日志记录**：在文档末尾「更新日志」章节补充本次更新的完整记录；
5. **一致性校验**：校验更新内容与代码逻辑的一致性、文档格式的规范性；
6. **输出备份**：按粒度差异化规则输出更新结果，模块/项目级文档自动覆盖原文件并保留历史备份。

## 标准化更新标记规范

### 1. 内容修改标记

```markdown
> 【更新于{YYYY-MM-DD}】：{变更原因}，{核心变更点说明}
```

## 全局通用规则
### 一、数据流设计规范

数据流核心原则：**单向流动、源头唯一、职责清晰**，所有数据流转必须贴合模块目录结构，明确 “数据从哪里来、到哪里去、如何操作”，禁止任何反向数据流、隐式数据流。

#### 1. 数据流分类
- 外部请求流：前端 / 外部服务的请求 → 接口层（Controller），仅通过 Request DTO 接收参数
- 业务处理流：接口层 → 业务逻辑层（Service），处理业务规则、逻辑流转，长链路需逐步骤注释
- 数据访问流：业务逻辑层 → 数据访问层（Repository），操作数据库 / 外部资源，仅通过 Entity 映射数据
- 响应返回流：处理结果 → 响应层，通过 Response DTO 格式化后返回给请求方

#### 2. 层间依赖规则
- 接口层（Controller）仅能依赖业务逻辑层（Service），禁止直接依赖数据访问层（Repository）
- 业务逻辑层（Service）仅能依赖数据访问层（Repository），禁止反向依赖接口层
- 禁止跨层直接调用，禁止反向数据流，保证职责完全分离

#### 3. 外部请求流规范
- 数据流入：仅通过 Request DTO 接收参数，所有参数定义类型，添加验证规则，仅接收最小粒度参数
- 禁止在接口层直接处理业务逻辑，仅做请求接收与响应转发

#### 4. 业务处理流规范
- 业务逻辑仅在 Service 层处理，禁止跨层处理业务规则
- 复杂逻辑必须拆分，单文件控制行数，长逻辑链路每一步必须添加注释，说明该步骤的作用与预期效果
- 禁止 Service 直接修改请求参数、直接操作请求 / 响应对象

#### 5. 数据访问流规范
- 数据操作仅在 Repository 层处理，禁止 Service 直接操作数据库连接
- 所有数据操作必须基于 Entity，禁止使用原生 SQL 操作无映射的表结构
- 共用数据查询必须上提至公共 Service，禁止重复查询相同数据

#### 6. 响应返回流规范
- 数据流出：仅通过 Response DTO 格式化返回数据，仅返回请求方需要的数据，禁止暴露内部敏感数据
- 禁止直接返回 Entity 实体，必须通过 Response DTO 做数据转换与过滤

#### 7. 禁止行为
- 禁止反向数据流、隐式数据流
- 禁止重复数据查询、数据冗余
- 禁止跨层处理业务逻辑、数据操作
- 禁止混用 Request DTO 与 Response DTO，禁止直接暴露 Entity 给外部

### 二、模块设计流程步骤

模块设计遵循 8 步流程，严格按顺序执行：
1. **需求拆解**：明确模块职责、拆解功能点、识别数据模型、梳理全链路数据流
2. **创建目录**：按规范创建模块根目录、子目录与基础文件，配置分类导出的 index 文件
3. **定义实体**：在 entities 目录中定义数据实体，继承 BaseEntity，使用 TypeORM Entity 装饰器，禁止使用 POJO
4. **定义 DTO**：在 dto 目录中定义 Request 与 Response 两类 DTO，区分请求参数与响应数据，添加验证与文档
5. **数据访问层**：编写 Repository 层，继承 BaseRepository，实现基于实体的数据增删改查操作
6. **业务逻辑层**：编写 Service 层，拆分复杂逻辑，控制单文件行数，为长链路添加逐步骤注释，实现事务与幂等性
7. **接口层**：编写 Controller 层，定义带版本的接口路由，绑定 DTO 验证，添加权限与文档，调用 Service 处理业务
8. **测试优化**：校验类型、数据流、各层职责，完成代码优化与规范校验

### 三、AI 生成强制约束

所有 AI 生成代码必须严格遵循以下规则，不可违背：
1. 严格遵循所有目录、命名、各层的规范，禁止自定义目录或文件结构
2. 数据模型必须使用 entities 目录下的 TypeORM Entity，必须继承 BaseEntity，禁止使用 POJO 作为数据实体
3. 所有 DTO 必须明确区分 .request 和 .response 后缀，禁止请求与响应类型混用
4. 所有子目录必须通过 index.ts 统一导出，对外仅暴露必要的模块资源
5. 单文件代码行数严格控制，禁止单文件超过 300 行（不含注释），复杂逻辑必须拆分到独立文件
6. 所有业务逻辑必须添加清晰明确的注释，长逻辑链路必须逐步骤说明每一步的作用、输入与输出效果
7. 数据流必须严格单向流转，禁止反向数据流、隐式数据流，各层职责必须清晰分离
8. 禁止使用 any、隐式类型，所有类型必须明确定义，禁止类型模糊
9. 导入导出使用相对路径，禁止循环导入、冗余导入，禁止导入未使用的模块
10. 禁止遗留调试代码、冗余代码，保持代码简洁、规范、可维护
11. 所有写操作必须使用事务，保证数据一致性，禁止无事务的跨表写操作
12. 所有分页查询必须使用统一的分页DTO与响应格式，禁止自定义分页实现
13. 所有接口必须添加版本前缀，支持接口版本迭代，禁止无版本的接口
14. 所有接口必须添加完整的Swagger文档，完善接口说明，禁止无文档的接口
15. 所有实体必须启用软删除，禁止物理删除数据，保证数据可追溯

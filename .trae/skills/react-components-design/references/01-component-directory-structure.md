# React+TS组件目录结构规范
## 核心职责
定义组件（父/子组件、页面子模块）的强制闭环目录结构，明确各目录的核心作用、递归规则、存在条件
## 边界范围
仅聚焦「目录层级/存在性」，不涉及文件命名、内容书写、逻辑实现
## 强制规范
所有组件（父组件、私有子组件、页面子模块）必须遵循以下闭环结构，子组件/子页面递归复用同套结构，禁止自定义目录或文件名：
```plain text
AComp（组件根目录，闭环单元）
├── index.ts            // 唯一对外出口：仅导出组件、组件Props类型，不写任何实现
├── AComp.tsx           // 视图编排层：仅做组件/子组件组装、UI渲染，无复杂逻辑、无数据请求
├── AComp.module.css|scss|less  // 样式层：CSS Modules 隔离，仅服务当前组件，不污染全局
├── types.ts            // 类型层：收敛所有类型（组件Props、store状态、事件回调、子组件类型等）
├── components          // 私有子组件层：仅当前组件可使用，子组件完全复用本套目录结构
│   ├── index.ts
│   └── BComp（子组件）
│       └── ...（同AComp目录结构）
├── pages               // 页面子模块层：仅「页面级组件」可存在，子页面递归复用本套目录结构
│   ├── index.ts
│   ├── A1（子页面）
│   └── A2（子页面）
│       └── ...（同AComp目录结构）
├── hooks               // 逻辑层：组件专属业务逻辑、数据获取、事件处理（不包含状态存储）
├── store               // 状态层：组件内部私有状态管理，不对外暴露
├── utils               // 工具层：纯函数、格式化、计算逻辑（无状态、无副作用）
└── context             // 通信层：组件内部跨层通信（子组件/子页面间），不对外暴露
```
### 补充约束
1. 仅 index.ts 对外暴露内容，store、context、hooks、utils 均为组件内部私有，不对外导出；
2. 子组件的 store 仅管理自身独有状态，共用状态统一在父组件 store；
3. 无私有子组件时可删除 components 空目录，无子页面时可删除 pages 空目录，无对应逻辑时可删除 hooks/store/utils/context 空目录。

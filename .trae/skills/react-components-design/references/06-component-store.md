# React+TS组件store层规范
## 核心职责
定义store目录的定位、文件结构、状态定义、状态操作规范
## 边界范围
仅覆盖store目录及状态管理全流程，不涉及其他目录、不涉及业务逻辑实现
## 强制规范
### 核心定位
store 仅用于 **当前组件内部私有状态管理**，存储组件自身的视图状态、本地数据，禁止存储全局状态、跨组件共享状态。

### 目录与文件规范
- store目录下文件统一命名：`index.ts`（唯一出口）、`store.ts`（核心实现），复杂逻辑可拆分`actions.ts`、`state.ts`，禁止自定义文件名
- `index.ts`仅导出store实例和状态修改方法，禁止导出内部实现
- store实例必须与组件强绑定，禁止全局store、跨组件复用

### 状态定义规范
- 所有状态必须在`types.ts`中定义类型，禁止无类型、any类型
- 状态结构 **扁平化**，禁止多层嵌套
- 状态分类：视图状态（isLoading等）、本地数据（localList等），共用数据必须上提至父组件store
- 禁止存储可通过Props派生、可通过utils计算得出的数据，避免冗余

### 状态操作规范
- 状态修改 **必须通过store暴露的方法**，禁止直接修改`store.state.xxx`
- 状态方法单一职责，语义化命名，一个方法仅修改对应状态
- 异步状态修改：在hooks中完成异步操作（接口请求），结果返回后调用store方法修改状态，**禁止在store中处理异步、发起接口请求**
- 子组件如需修改父组件状态，通过父组件传递的回调触发，禁止直接操作父组件store

### 禁止行为
- 禁止store存储全局、跨组件共享状态
- 禁止直接修改store状态
- 禁止在store中写业务逻辑、接口请求
- 禁止子组件重复存储父组件的共用数据
- 禁止对外暴露store内部实现

# 开题报告  
## 1 选题目的及研究意义  
「中小企业在 MySQL 与 Excel/CSV 的日常分析中缺乏统一语义和低门槛工具，IT/业务协作成本高，数据口径分裂。[1，关键词：自助分析，MySQL，低代码可视化]」  
「通过设计基于 JSON Schema 的查询 DSL，前端拖拽生成查询意图，后端适配 MySQL 与 CSV/Excel，可在不依赖手写 SQL 的前提下降低使用门槛。[2，关键词：查询 DSL，JSON Schema，可视化查询]」  
「统一的轻量语义层能减少口径不一致，提升数据复用和可解释性。[4，关键词：语义层，维度指标抽象]」  
「私有化、轻量化的部署形态更契合企业内网与合规要求。[5，关键词：私有化部署，轻量 BI]」  
「引入 NL→DSL、图表类型推荐等 AI 辅助能力，可进一步降低业务人员学习成本，但保持对执行链路的可控与校验。[6，关键词：NL2Query，Chart Recommendation]」

## 2 国内外研究现状  
### 2.1 国内研究现状  
「国内自助 BI 与低代码查询工具在中小企业场景增长，常以 SQL 模板和拖拽式交互降低门槛，但语义层普遍简化。[7，关键词：自助 BI，中国，中小企业]」  
「数据中台场景中，JSON/DSL 用于描述查询并解耦前后端，提升模板化与安全性。[8，关键词：JSON DSL，数据中台，模板化查询]」  
「轻量语义层聚焦字段别名、基础聚合与单层表关系，避免复杂血缘导致的实现不可控。[9，关键词：语义层简化，字段映射，聚合定义]」

### 2.2 国外研究现状  
「现代 BI 平台采用中间 DSL/AST 生成参数化 SQL，以实现多源适配与防注入安全。[10，关键词：BI DSL，SQL generation，parameterized queries（外文）]」  
「针对表格数据的可视化推荐利用数据分布与字段语义生成默认图表与查询建议。[11，关键词：table data visualization recommendation（外文）]」

## 3 相关技术原理及技术路线  
「DSL 以 JSON Schema 描述维度、指标、过滤、排序、分组、分页与数据源信息，便于前端拖拽生成、后端校验与转换。[2，关键词：查询 DSL，JSON Schema，可视化查询]」  
「适配器模式分离数据源差异：MySQL 侧将 DSL 转换为参数化 SQL，避免注入并支持模板复用；CSV/Excel 侧将 DSL 转换为 DataFrame 操作以完成过滤、聚合与排序。[3，关键词：自助 BI，参数化 SQL，模板化][12，关键词：DataFrame query translation，CSV analytics]」  
「轻量语义层仅覆盖字段别名、类型、基础聚合和一跳表关系，不做多跳推断，以保持复杂度可控。[4]」  
「可视化层采用统一数据格式驱动折线、柱状、饼图与表格，并以配置 Schema 描述图表与看板布局。[11]」  
「AI 辅助模块提供 NL→DSL 草案与图表推荐，但不直接生成或执行 SQL，需经 DSL 校验与人工确认以确保可控性。[6]」

技术路线：  
「数据接入阶段完成 MySQL 连接与 CSV/Excel 上传，并生成元数据与字段清单；语义建模阶段定义数据集、维度/指标与基础聚合；查询构建阶段由前端拖拽生成 DSL 并通过 JSON Schema 校验；执行阶段由适配器分别对 MySQL 与 CSV/Excel 进行转换执行并输出统一结果；可视化阶段依据图表配置生成视图并支持看板布局；AI 辅助阶段提供 NL→DSL 草案与图表推荐；安全审计阶段实施参数化查询、权限与日志；最终以轻量后端与前端单页支持本地或内网部署。[10][11][13，关键词：SQL injection prevention，audit logging]」

## 4 研究难点及目前存在的问题  
「DSL 的表达力与简洁性需要平衡，避免因多方言兼容导致实现复杂化。[10]」  
「MySQL 与 CSV/Excel 在类型、聚合与空值处理上的差异会影响跨源一致性。[12]」  
「语义层若超出别名与基础聚合，复杂血缘与多跳关系将大幅增加实现风险。」  
「AI 辅助需避免直接执行生成结果，必须经校验与人工确认以保证安全可控。[6]」  
「前端拖拽与 DSL 同步需要高效校验与错误提示，避免用户体验受损。」  
「私有化部署场景要求最小可用的权限与审计方案，兼顾安全与易用。[13]」

## 5 拟采取的措施  
「以 JSON Schema 明确定义必填/可选字段、类型与枚举，限制表达空间以提升可控性。[2]」  
「为不同数据源实现统一适配接口，封装类型映射与聚合差异，保持结果格式一致。[12]」  
「语义层保持最小化：字段别名、类型、基础聚合与一跳关系，避免血缘与多跳 join 推断。[4]」  
「全链路校验与安全：前后端双重 DSL 校验，MySQL 全程参数化，CSV/Excel 仅允许受控计算与导出。[3][13]」  
「AI 辅助输出仅为草案，需人工确认后执行，关键字段与聚合需显式标示来源与含义。[6]」  
「性能与体验优化：MySQL 使用 LIMIT/OFFSET 与必要索引提示，CSV/Excel 采用列裁剪、流式读取与缓存；前端对 DSL 校验与错误回显做实时提示。[11][12]」

## 6 研究预期成果  
「交付一套可私有化部署的轻量可视化查询原型，支持 MySQL 与 CSV/Excel。」  
「形成完整 DSL Schema（含校验规则）与适配器实现，覆盖查询到结果格式的全链路。」  
「提供轻量语义层管理与拖拽式查询界面，支持基础图表与看板。」  
「实现 AI 辅助的 NL→DSL 草案与图表推荐能力。」  
「完成系统文档与论文，包括架构设计、DSL 规范、适配器实现、实验与评估。」

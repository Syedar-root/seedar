# AI 模块概览

## 1. 模块职责

AI 模块当前不是普通聊天模块，而是四部分能力的组合：

1. AI 模型配置管理
2. 会话管理
3. 流式聊天
4. workflow interrupt 与工具调用

它承担的是“智能能力中台 + 页面侧助手”的双重角色。

## 2. 为什么它特殊

它并不是只驻留在后端，也不是只驻留在前端，而是贯穿前后端协同：

- 前端负责会话 UI、消息流、interrupt 恢复、动作分发
- 后端负责模型、代理、工具、技能、图执行

也就是说，这个模块天然是跨层模块。

## 3. 设计目标

从实现反推，它至少想达到以下目标：

1. 让用户以自然语言方式表达分析或搭建诉求。
2. 让 AI 理解当前页面上下文，而不是脱离页面给出泛泛回答。
3. 让 AI 能借助工具获取数据集、查询结果等结构化信息。
4. 让 AI 在必要时驱动前端 workflow，而不只是给建议。

## 4. 核心对象

### 4.1 `Ai`

表示平台中可用的模型配置对象。

### 4.2 `AiSession`

表示一次会话上下文与状态。

### 4.3 `AiChatScene`

表示当前前端页面上下文，是 AI 实现页面感知的关键输入。

### 4.4 `WorkflowRunInterrupt`

表示后端希望前端执行某个 workflow 的中断对象。

### 4.5 `AskUserInterrupt`

表示 AI 需要继续向用户提问以澄清需求的中断对象。

## 5. 关键实现特征

### 5.1 多模型适配

系统可以通过配置适配 OpenAI、Anthropic、DeepSeek。

### 5.2 Skill 化组织

AI 能力不是单一 prompt，而是按 skill 拆分，如：

- `data-query`
- `chart-recommend`

### 5.3 Workflow 恢复机制

AI 触发的 workflow 并不是一次性执行，而是“中断 -> 前端动作 -> 恢复会话”的闭环。

## 6. 论文可用描述

“AI 模块采用前后端协同设计：后端基于大模型、工具系统和图式 agent 构建智能推理与任务执行能力，前端则负责会话展示、场景注入与 workflow 动作恢复，从而使 AI 不仅能够进行自然语言交互，还能够参与具体分析任务的页面级辅助执行。”

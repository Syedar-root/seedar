# 面板与仪表盘模块概览

## 1. 模块职责

这个模块实际包含两层资产：

- `Panel`：查询结果的可视化资产
- `Dashboard`：多个 Panel 的组合与布局资产

Panel 解决“一个分析结果如何显示”的问题；Dashboard 解决“多个分析结果如何组合交付”的问题。

## 2. 设计动机

为什么不把仪表盘直接设计成“图表集合 JSON”，而要拆成 `Panel + Dashboard` 两层？

原因主要有：

1. 面板本身可以复用。
2. 仪表盘可以只维护组合关系与布局。
3. 单个面板可以独立编辑、预览、发布。
4. 前端组件层可以围绕 Panel 做更细粒度渲染。

## 3. 核心边界

### 3.1 Panel 负责

- 标题
- 类型
- 状态
- 查询绑定
- 可视化配置
- 尺寸信息

### 3.2 Dashboard 负责

- 名称
- 布局
- 面板关系
- 编辑/浏览工作台形态

## 4. 前端实现中心

这一层最核心的前端复用能力是 `SeedarDashboard`。

它统一承载：

- 面板网格
- 拖拽布局
- 编辑工具栏
- 添加 / 移除面板触发器
- 与业务页面无关的布局基础设施

这意味着项目不是把仪表盘逻辑全部写死在页面里，而是提炼出了平台级组件。

## 5. 关键实现特征

### 5.1 资产复用而非副本复制

仪表盘不是复制面板内容，而是引用已有面板。

### 5.2 布局 JSON 化

仪表盘布局作为 JSON 保存，便于：

- 响应式断点扩展
- 前后端传输
- 后续复制、迁移和版本演化

### 5.3 编辑态与浏览态分离

页面上存在：

- `edit`
- `view`

两种模式，说明系统显式区分“搭建过程”和“消费过程”。

## 6. 论文可用描述

“面板与仪表盘模块构成了系统的可视化交付层。其中，面板对象负责封装查询结果与可视化配置，仪表盘对象负责组织多个面板并维护其响应式布局信息。该设计将展示资产与组合资产分离，提高了分析内容的复用性与页面编排能力。”
